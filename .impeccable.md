# Quanto guadagno: design context

Approved mockups v2.1 (29 September 2026). Living reference: `/style-guide` (noindex). Source of the
decisions: `quantoguadagno-handoff/design/NOTES.md` and `CRITIQUE-v2.md`.

## Users and tone

Italian workers with one number (a gross salary, a turnover, a last day of work) and one question.
Some stop at the answer, some read every line that produced it. The page serves both without asking.

Preciso, sobrio, leggibile. Authority comes from showing the arithmetic, not from decoration.

## Identity

- An Italian busta paga, typeset properly: white paper, black ink, one blue, ruled rows, tabular
  figures. No cards, panels, shadows, gradients or tinted boxes.
- GOV.UK interaction and content patterns, without GOV.UK branding.
- Dark mode is the negative of the same structure, never a warm tint. Print is always light.
- Phone and desktop are equals: same content, same DOM order; CSS changes the layout only.

## Principles

1. **The number is the content.** The result figure is the largest thing on the page.
2. **One spot colour.** Blu is for links, the focus ring, the rule under the figure and the active
   comune option. Under 5% of any screen. Money is never coloured; a deduction is a negative
   amount with U+2212, not red text.
3. **Rules only where they separate something.** 1 px filetto between rows. 2 px ink above a
   total, a notice, and every section heading: `qg-band` below the calculator, the fields after
   the result (`qg-calc__rest`), each offer. A row never looks like a section break. Blocks inside
   the result (assumptions, ledger, table captions) share one 17 px heading and no rule of their
   own. Radius 2 px on inputs and buttons only.
4. **One motion moment.** The figure settles for 150 ms. Hover and focus change colour only.
   Nothing moves under `prefers-reduced-motion`.
5. **Sentence case everywhere.** No capitals, letter-spacing, eyebrows or arrows appended to links.
   Buttons start with a verb. "Tu".
6. **One obvious primary action per screen.** Secondary actions are links or link-styled buttons.

Theme: the head script sets `data-theme` on `<html>` from `qg.theme` (`light`, `dark`, absent =
system). Without the script the system preference applies. `palette.test.ts` fails if the two
files drift or a text pair drops under 4.5:1.

Type: Archivo only, self-hosted in `public/fonts` (`scripts/fetch-fonts.sh`). Widths: 125% at
weight 600 for the wordmark and standalone figures, 100% for text, 87.5% for dense tables below
45rem. Weights 400, 500, 600 only. Components use role tokens, never a raw step: `--t-small`
15/17, `--t-body` 17/19, `--t-lead` 19/24, `--t-h4` 17/19, `--t-h3` 19/24, `--t-h2` 24/32,
`--t-h1` 32/48 px (phone / from 45rem, a viewport query in `tokens.css`). Fixed exceptions: 13 px
for chart ticks and the payslip, 15 px for the header nav. `--t-cifra` and `--t-cifra-sm` are sized
on the result column (`cqi`). Line heights 1.55 / 1.45 / 1.35 / 1.15 / 1. Tabular figures in
tables, ledgers, inputs and the bar; proportional on a standalone number.

Space: `--s-1`…`--s-9` = 4, 8, 12, 16, 24, 32, 48, 64, 96 px. Targets 44 px, controls 48 px, focus
ring 3 px blu with a 2 px offset, text measure 52ch, page 1280 px.

Controls: fields, selects, segmented bars, checkboxes and radios share one rule, a 2 px ink border
on white (GOV.UK weight). Labels and group titles are weight 600 at body size. Checkboxes and
radios are 28 px. A field in error gets a 4 px `--errore` bar on its start edge, the message in
bold above the control and an `--errore` border; the bar comes with the message, never before.

## Layout

Container queries on `.qg-page` (the page minus the scrollbar):

- below 45rem: one column, 16 px gutters, stacked tables, `qg-table__wide` hidden
- 45rem: 32 px gutters, h1 33 px, menu panel in three columns, footer sitemap
- 60rem: calculator grid (primary fields, result, other fields) with a sticky summary, article
  with a sticky contents list, 40 px gutters
- 77.5rem: full header nav and the language link (the row needs about 1,120 px)
- `max-height: 30rem`: sticky elements become static

Templates: `BaseLayout` (document and chrome), `TextPageLayout` (breadcrumbs, then the island),
`ToolPageLayout` (the island area). Islands render their own `PageIntro` and use
`CalculatorLayout` (`qg-calc`) or `LongForm` (`qg-article`) from `src/components/page`.
Anything `position: fixed` (the phone bar) renders outside `.qg-page`, portalled to `body`.

Every calculator has the same order: primary fields, result, then `rest` opening with "Personalizza
il calcolo". Tables and charts that expand on the result (anno per anno, mese per mese, livelli)
are full-width bands below the calculator, never in the form column. Topics close the page as a
band titled "Per capire …". The footer drops its sitemap on pages that show the tool list.

## Chrome

- Below 77.5rem the menu is one `<details data-disclosure="inline">`: opens without JavaScript,
  pushes the page down, ends with language, theme and "Chiudi il menu".
- From 77.5rem each group is `<details name="qg-nav" data-disclosure="overlay">`; a group with a
  single tool is a direct link.
- `disclosureScript` (inline, CSP-hashed) closes on Esc (focus back to the summary), on a click
  outside or when focus leaves a nav panel, and runs the close button. Controls that need it carry
  `data-requires-script` and stay hidden without it.
- Theme: radios in the menu and the footer, kept in sync by `themeScript`; hidden without script.
- The current language is text, not a link. The other language links to the same page.
- Breadcrumbs only on text pages, ancestors only. No sticky header on phones.

## Accessibility floor

WCAG 2.2 AA. Visible labels, 44 px targets, focus visible and never under a sticky element, reflow
at 320 px with no sideways scroll (a table that must scroll goes in `qg-table-scroll` with
`tabindex="0"`, `role="region"` and a label), `role="list"` on styled lists, explicit roles on
stacked tables, forced-colors support (outlines and borders, no `box-shadow` for meaning),
logical properties only, `:dir(rtl)` mirrors directional icons, amounts isolated with `<bdi>`.

## Formats and copy

Money "1.234,56 €" (no-break space, U+2212 minus); thresholds in prose in whole euros; "circa" for
rounded estimates. "9,19%". "28 settembre 2026". Apostrophe U+2019. Acronyms expanded at first
use. "Netto mensile" always with its basis. No "clicca qui", no exclamation marks, no badges
beyond "Da verificare" and "Provvisorio".

## Code rules

- Classes `qg-block__element--modifier`, named after the component, one file per component in
  `src/styles/components/`, imported in order by `src/styles/global.css`. Style-guide-only states:
  `.is-hover`, `.is-focus`, `.is-current`.
- Colours, sizes and spaces only through tokens. No inline `style` attributes (CSP).
- Text pages ship 0 KB of JavaScript (`pnpm check:budgets`).
- Every new component gets a section in `src/components/style-guide/` listed in `sections.ts`.
- Calculator views are built from the React kit: `src/components/form` (Field, Fieldset, TextInput,
  MoneyInput, NumberInput, Select, RadioGroup, Checkbox, DetailsGroup, Combobox, ComuneField,
  ErrorSummary, `useBlurErrors`) and `src/components/result` (ResultFigure, Assumptions, NoteLine,
  Ledger, WorkedSum, Actions, BottomBar, LiveStatus, BracketIndicator, RaiseImpact,
  YearComparison, Topics). Their strings live in the `form` namespace, which every calculator
  loads. Specimens: `/style-guide`, sections "Campi del modulo", "Ricerca del comune", "Risultato
  e dettaglio".
- Errors appear when a field loses focus, after the click that caused it, and disappear as soon
  as the value is valid. Live calculators never show an error summary.
